# ClawMaster 笔记

[English](README.md) | 中文

## 概述

ClawMaster 内置本地笔记库，支持带格式的文档编辑、Markdown 源码、双向链接、反向链接、标签与全文搜索。你可以让 agent 把完成的工作记录成笔记，或者存储可审阅的草稿并展示 diff，保持源笔记不变；agent 对笔记的改动需要你批准。笔记库由产品自建，不依赖 Obsidian。已保存的笔记仍是普通文件；未保存的草稿在本次应用会话内保留在内存中。

## 使用本包

这个私有组件通过[捆绑补丁](cordis.patch.yml)包含在 ClawMaster 桌面配置中。从侧栏标签选择器打开 **笔记**。插件加载时 host 会创建配置的笔记库，并在其中没有任何受支持笔记时写入一篇欢迎笔记。

选中笔记后，目录会收起，让编辑器使用面板的可用高度。通过工具栏的 **笔记目录** 显示或隐藏目录。宽面板中目录在编辑器旁打开；窄面板中目录覆盖编辑器，选择笔记或关闭目录即可返回正文。需要更多空间时，使用宿主侧栏的全屏控件。

打开笔记即可直接编辑带格式的文档。停止输入片刻后，笔记会自动保存修改；源码编辑使用相同的保存流程。状态显示 **保存中…** 或 **已保存**。退出应用前，请确认修改已保存。

编辑正文上方的 **文件名** 即可更名。按 Enter 或离开输入框提交名称，按 Escape 恢复原名。更名保留父文件夹与 Markdown 扩展名，不修改正文中的标题或 YAML 头部；这些内容与文件名分别维护。

需要正文、标题、引用、粗体、斜体、行内代码、列表、任务列表、链接、表格、分隔线或代码块时，打开 **更多笔记操作 → 显示格式工具**。同一菜单中的 **Markdown 源码** 显示包含 YAML 头部的完整源码；格式受支持时可选择 **返回文档**。**删除** 需要确认，且不进入回收站。**今日笔记** 打开当天的日记笔记，且只创建一次。

仅打开笔记或切换视图而不编辑，会保留原始源码，也不会保存。实际修改文档时保留原始 YAML 头部和正文前后的空白，正文则序列化为常规 Markdown；需要精确保留正文格式时，请使用源码编辑。不支持的构造，包括代码以外的双向链接、嵌入图片、原始 HTML 和开头的缩进代码，会保留草稿并在源码视图显示提示。回退本身不会转换或保存，之后的源码编辑会自动保存。

保存失败或版本冲突会暂停自动重试并保留草稿；冲突不会覆盖更新后的文件。处理原因后，选择 **更多笔记操作 → 重试保存**。发生冲突时，先比较最新内容与草稿；**重新载入** 会在丢弃草稿前明确询问。继续输入不会绕过已暂停的保存。

选择其他笔记会等待当前保存尝试结束。失败后仍可离开，同一 Session 会保留草稿与错误。关闭「笔记」标签会发起后台保存尝试；插件保持加载时，重新打开会接回进行中的保存及保留的错误。创建、重命名、删除笔记与应用建议，都要求当前草稿先保存成功。

**笔记信息** 中的 **链接笔记** 列出已载入或已保存笔记中的双向链接目标。可在此打开目标；有多篇匹配时由你选择，一篇都不匹配时提供创建入口。同一区域仍可查看反向链接。`.canvas` 文件以只读方式打开，编辑与重命名被禁用，因为本组件没有画布编辑器。

**笔记信息** 默认收起，展开可查看标签、反向链接和 **待审建议**。收起时仍显示待审建议数量。展开后先核对建议的 diff，再明确选择 **应用** 或 **丢弃**；打开信息区不会应用修改。应用受修订号保护：若笔记在起草之后被改动，应用会被拒绝，建议保留下来供重试。保存失败或冲突时保留草稿，并阻止应用建议。

标签页可见时，面板每四秒轮询同时涵盖笔记与待审建议的版本号，因此外部编辑以及建议的创建或丢弃无需手动刷新即可出现。该刷新绝不会丢弃未保存的草稿：面板会报告外部改动并提供重新载入。笔记、标签与建议刷新分别完成；建议列举失败时保留错误与重试入口，已成功加载的笔记和标签仍可使用。

<a id="configuration"></a>
## 配置

[host 配置](src/host.ts)接受一个绝对路径 `vaultRoot`。macOS 上的默认值是 `~/Documents/ClawMaster 笔记`，其他平台为 `~/ClawMasterNotes`，均位于桌面运行时目录之外。读取、写入、列举、搜索、标签与反向链接共享以下上限。每次笔记写入在改动文件前检查最终 UTF-8 字节数，包括日记头部和追加内容；拒绝时保留已有字节与修订号。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `limits.maxReadBytes` | 262144 | 单篇笔记读写的最终 UTF-8 字节数、已存建议 JSON 累计字节数或 diff 前后文本累计输入的上限。 |
| `limits.maxTreeEntries` | 5000 | 一次笔记或建议列举的最大条目数；新增建议时也校验已存建议条数。 |
| `limits.maxSearchResults` | 50 | 搜索命中的默认值与上限；最高可配到 200。 |

<a id="understand-the-implementation"></a>
## 实现说明

<details>
<summary>实现内部细节</summary>

[host](src/host.ts)在既有、已认证的 DSH Fetch 载体上注册八条路由：位于 `/api/clawmaster/notes/` 下的 GET `tree`、`note`、`search`、`tags`、`backlinks`、`proposals`、`revision`，以及 POST `command`。认证与来源校验由该载体负责；浏览器使用同源凭据。不额外启动任何服务器。工具定义、执行上下文与审批都使用 DSH 的公开类型。卸载时撤下注册、取消待处理审批，并等待进行中的工具、请求与修订扫描。Host 与 Client 必须一起交付：只更新客户端无法补齐缺失的 API 路由。

[vault](src/vault.ts)会拒绝其规范根目录之下的链接文件与链接目录。协作型写者共享一把跨进程文件锁；修订校验与改动回执都在持锁期间计算。保存通过原子替换发布完整临时文件。创建与重命名使用硬链接并拒绝占用的目标。[共享文本解析](src/note-format.ts)不会重写 frontmatter，浏览器渲染的是解析后的 Markdown 数据而非原始 HTML。

[建议存储](src/proposals.ts)将草稿与基础修订号以 JSON 持久化在 `.clawmaster/proposals` 下，不进入笔记索引，但外部文件系统访问仍可读取。元数据复用笔记库路径检查、有界读取、写锁与原子无覆盖发布。新增建议在笔记库写锁内检查已存条目数与累计 JSON 字节数。列举使用相同限制；建议文本与源文本另共享一份累计 diff 输入预算。不安全路径、损坏元数据与超限字节会明确报错。[行级 diff](src/diff.ts)在单侧超过 2000 行时使用整文件替换，并标记截断输出。

[修订扫描器](src/watcher.ts)按请求根据笔记路径、大小与修改时间计算指纹，并发请求共享扫描。`revision` 路由将该指纹与有界的建议内容摘要合并，因此只改元数据也会刷新面板。扫描失败由请求报告；卸载会等待进行中的扫描。不启动原生文件系统监听或后台扫描。

[面板](src/client.tsx)在 [Session 保存队列](src/autosave.ts)中保留各篇笔记的完整 Markdown 草稿与读取版本。两种编辑方式均在停止输入 600 ms 后保存，队列串行执行各篇笔记的请求。成功时仅推进已提交的快照，后续输入继续排队；失败后暂停该笔记的自动重试，等待显式重试或确认重新载入。[文档适配器](src/rich-editor.tsx)将原始 YAML 头部与正文外围空白从可编辑正文中分离，忽略初始化规范化，并将不支持的输入切回源码模式。MDXEditor 4.2.5 连同其 MIT 许可声明打包到压缩的浏览器产物中；CodeMirror 语言支持自动加载已禁用。[树](src/tree.ts)按笔记 id 推导嵌套文件夹，并使用宿主资源管理器的行间距；[图标](src/icons.tsx)使用内联 SVG。

</details>

<a id="model-experience"></a>
## 模型侧体验

`notes_query` 无需写入批准即可读取配置的笔记库，包括待审建议。`notes_propose` 起草一处改动并返回其行级 diff，**不写入任何笔记**，同时将建议 JSON 持久化到本地，无需额外批准。`notes_write` 负责创建、保存、追加、重命名、删除、追加带日期的日记条目，以及应用和丢弃已存储的建议。`notes_digest` 由「做了什么」加上可选的决策、证据与下一步合成一条带日期的条目，链接到匹配的项目笔记，并追加到日记；这就是把完成的工作变成笔记的原语。

通过 `notes_write` 和 `notes_digest` 修改笔记时，要求发起方是 DSH agent 会话并取得 `allowed-once` 批准；被拒、被取消或插件卸载都会阻止待处理审批提交。保存必须携带从读取得到的修订号，不一致时返回冲突。应用建议必须携带草稿所依据的修订号，发生漂移即被拒绝。回执报告改动前后的修订号，而不提供被删除或被替换内容的可恢复副本。直接经由已认证 UI 的命令属于用户编辑，不会额外请求 agent 批准。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与后续工作

- 不支持的文档构造仍可通过 [Markdown 源码](#use-this-package)编辑。本组件不实现 Obsidian 插件或画布编辑器。搜索是扫描文件而非持久化索引，列举会为标题读取每篇笔记的头部。
- 实时刷新依赖轮询，失败请求或隐藏标签页可能延迟刷新。笔记指纹无法检测同时保持大小与修改时间不变的编辑。
- 草稿和待保存队列不会跨进程退出或崩溃持久化。关闭标签只是发起保存尝试，不保证进程退出前保存完成。存在草稿时浏览器会收到卸载警告；原生应用退出保护尚未验证。
- 文件锁协调的是协作型写者；它们无法隔离恶意或不配合的进程替换祖先目录或竞争最后一次文件系统操作。写入不承诺通过 `fsync` 获得崩溃持久性。
- 创建与重命名需要硬链接支持。重命名清理失败可能留下两个路径，并给出显式错误。异常退出遗留的锁需要人工核查与恢复；本组件不会自动清除它。

<a id="verification"></a>
## 验证

在已安装开发依赖的仓库根目录下，运行存储/host 测试、编译客户端测试、类型检查与产物新鲜度检查。客户端运行器会先构建产物，因为它驱动的是已发布产物而不是源码：

```sh
npm --prefix frontends/notes test
npm run test:notes-client
npm --prefix frontends/notes run typecheck
node frontends/notes/scripts/build.mjs --check
```

这些检查使用合成文件与受控的浏览器响应；它们不构成对最终安装后「笔记」界面的验收。
