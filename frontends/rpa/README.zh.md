# @clawmaster/dsh-rpa

[English](README.md) | 中文

## 概要

ClawMaster 的自动化组件是 DSH 之前那套原生控制面，现在作为 DSH 组件恢复回来。DSH 桌面迁移丢掉了
`codex/clawmaster-before-dsh` 分支上那套受治理的 RPA；这个组件把它取回来，而不是重新设计一遍已经能用的东西。

有两处性质值得恢复而不是重写。模型永远不提供 PID 或坐标：它从本组件产出的产物里选择窗口引用与元素引用，
由原生侧解析元素中心点并发出输入事件。而且一旦动作触碰了桌面，中断之后绝不会自动重放——它会变成
`unknown_outcome` 等待人工处理。

## 目录内容

| 部分 | 它是什么 |
| --- | --- |
| `seam/` | 恢复出的 TypeScript 控制面，逐字还原：契约、端口、受策略约束的运行器、带版本校验的文件存储，以及按运行隔离的 Web 驱动。 |
| `src/` | DSH 宿主半：三个面向模型的工具、通往原生助手的进程桥，以及 fail-closed 的策略端口。 |
| `native/` | 恢复出的 Rust 控制面：辅助功能快照、物理输入、隔离的浏览器 profile 与加密产物存储。 |
| `tests/` | 针对替身 DSH 上下文的宿主演习，以及既驱动替身进程、又（在构建后）驱动真实助手的桥接测试。 |

## 工具

| 工具 | 读或写 | 它做什么 |
| --- | --- | --- |
| `rpa_run` | 只写无副作用步骤 | 通过持久化存储驱动运维安装好的工作流运行。 |
| `rpa_native` | 只读 | 报告助手能力清单、恢复出的工具目录，或有界的桌面快照。 |
| `rpa_call` | 取决于具体工具 | 转发一次恢复出的 `rpa_*` 调用，例如 `rpa_windows`、`rpa_snapshot` 或 `rpa_extract`。 |

## 治理边界

- 工作流由运维声明。模型可以启动已安装的工作流，但无法自己编造步骤。
- 助手的 `input` 子命令没有被暴露，所以这个构建无法在裸坐标上输入或点击。
- 在审批桥接好之前，带外部副作用的步骤是被拒绝而不是排队。
- `approve` 不是模型动作，所以任何东西都无法批准自己的外部动作。
- 被中断的外部动作会变成 `unknown_outcome`，且绝不自动重试。

## 验证

```sh
node scripts/build.mjs --check
node --import tsx/esm --test tests/*.test.mjs
(cd native && cargo build --bin clawmaster-rpa-native)
```

- 没有 macOS 辅助功能授权时，助手会拒绝桌面快照，并指明需要更改的具体设置项。
- 助手未构建时，桥接报告为不可用，而不是抛错。
- 恢复出的缝自带测试套件在这个组件里依然全部通过。
