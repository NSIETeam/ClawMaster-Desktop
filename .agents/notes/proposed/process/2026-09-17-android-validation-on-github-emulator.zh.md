# Agent Note: 在 GitHub 托管模拟器上验证安卓应用

Status: proposed

[English](2026-09-17-android-validation-on-github-emulator.md) | 中文

## Problem

安卓构建和设备测试不应占用用户电脑资源；仓库的安卓 README 虽然描述了模拟器验证，但仓库没有对应的安卓工作流。

## Proposal

使用带硬件加速安卓模拟器的 GitHub 托管 Linux 运行器，在 API 26 和 API 36 上执行安卓发布构建和仪器测试。生成一次性 CI 签名密钥，核对 APK 签名和校验和，并短期保留 APK 与证据作为验证产物。该产物不是公开发行包，也不能替代使用长期保管的发布密钥签名。

同一工作流还会使用 NDK r28.2 交叉编译固定版本的 Node.js 22.19.0 源码，目标为 Android arm64 和 x86_64，并使用运行器上的主机编译器构建构建期工具。工作流会检查 16 KB ELF 段对齐，并在 Android 16 的 16 KB 模拟器上启动 x86_64 二进制。源码构建会应用一个小型 Android 兼容补丁，处理 V8 陷阱处理器、cctest 保护页、zlib CPU 检测和 V8 的 `execinfo` 路径。Node.js 上游不支持 Android；运行冒烟检查成功并不代表安卓应用已内嵌 DSH、支持 DSH 原生扩展或通过 Node.js 测试套件。

此工作流覆盖当前独立安卓实现。桌面功能对齐仍是单独的产品要求，不能从构建或模拟器运行成功中推断已经完成。

## Alternatives considered

**在用户电脑上运行模拟器。** 这会占用本地内存和 CPU，与所有安卓模拟器工作放在 GitHub 的要求冲突。

**发布每个成功工作流生成的 APK。** CI 密钥是一次性的，其签名不能用于原位升级，也不能证明这是可分发的正式版本。

## Acceptance criteria

- 工作流在 GitHub 托管安卓模拟器上执行安卓构建与仪器检查，不在本地启动模拟器。
- 工作流交叉编译两个 Android 64 位 Node 目标，检查 ELF 加载段对齐，并在 16 KB 安卓模拟器上运行 Node 子进程冒烟测试。
- 记录 CI APK 的校验和与签名证书，并将清楚标记为验证包的产物保留七天。
- 安卓文档仅描述工作流实际执行的检查，并说明验证不能证明桌面功能对齐或正式发布签名。

## Risks

GitHub 运行器、SDK 下载或模拟器启动可能出现与产品行为无关的失败。当前原生安卓应用缺少桌面 DSH 功能，因此仅通过云端验证仍未达到用户要求的功能对齐。
