# Agent Note: ClawMaster 0.2.3 交付规划

Status: proposed

[English](2026-09-15-clawmaster-0.2.3-delivery-plan.md) | 中文

## 问题

ClawMaster 需要可预期的升级、可恢复的编辑和可核验的工作成果。桌面与 Android 0.2.2 发布线提供不同能力，源码提交也各自独立。安装包已发布、Session 空闲和组件已暂存分别描述不同结果；任何一项都不能单独证明用户的工作已经完成或可以安全继续。

本文是拟议 0.2.3 迭代的实施与验收计划。所有未勾选项目均为待办，不代表功能已经交付或测试已经通过。计划本身不授权发布、访问私密聊天、付费模型运行或更改用户已安装的应用。后续组件文档只能描述实际交付的行为。

## 提案

保留 Tauri 桌面壳，复用 DSH 的模型、凭证、Session、工具、审批、Goal 和投影。交付五个工作包：组件生效与恢复、草稿与备份、WatchDog 验收、安卓更新、协同发布验证。先完成 P0，再扩展 P1；取得候选版证据后才确定发布日期。

桌面目标版本暂定 0.2.3。Android 保持独立版本与标签，只有本端修改和验收完成才提升版本。发布计划必须把每个受支持平台明确记为更新到指定版本，或保留指定版本并说明原因。版本号相同不是验收要求。

<a id="updates"></a>
## A：更新生效与恢复

用户结果：现有设置或更新入口能解释组件处于可更新、已下载、已暂存、已生效还是失败。重启会应用受支持的暂存变更，并确认运行版本。复用[组件安装](../../../../frontends/updates/src/components.ts)、[更新操作](../../../../frontends/updates/src/service.ts)、[首次挂载](../../../../frontends/updates/src/bootstrap.ts)和[桌面壳](../../../../apps/desktop-tauri/README.zh.md)。

### 实施顺序

1. A1 用同一操作身份记录候选版本/摘要、当前 profile 修订、前一组件引用、预期激活方式和观测结果。保留已有认证下载及归档校验，不增加任意 URL 或路径参数。
2. A1 区分 profile 修改与 Loader 成功。健康结果必须绑定实际 Host、组件实例和版本；仍运行旧组件的健康进程不能确认新版本已经激活。
3. A2 由桌面壳等待编辑器和活动工作达到约定停止点，停止其拥有的 Host 进程树，重新检查候选字节和 profile 修订，应用暂存变更并重新启动。取消退出时保持当前应用可用，操作仍为暂存。
4. A3 升级已有独立更新器 0.1.0/0.1.1，保留无关设置和停用选择。升级使其支持新版原生清单通道，现有组件目录地址不变。
5. A3 在激活失败且记录的 profile 修订仍匹配时，恢复前一个兼容组件。用户已改配置时停止并保留两个版本，不覆盖这些修改。恢复尝试必须有上限，坏组件不能造成重启循环。

### 必须覆盖的用例

| 用例 | 准备与操作 | 必须观察到的结果 |
| --- | --- | --- |
| U-01 | 保持一个 Session 打开，升级一个受支持热更新组件 | 实际调用使用新版本；Session 和凭证仍可用 |
| U-02 | 升级一个须重启组件及更新器自身 | 先报告暂存；只有停止 Host 后应用并观测到新版本，才报告生效 |
| U-03 | 编辑器含改动时取消退出 | 应用保持可用；未替换组件，编辑未丢失 |
| U-04 | 中断下载、破坏字节、使用错误签名或耗尽磁盘空间 | 当前运行时可用；未经验证的候选不能激活 |
| U-05 | 批准后修改 profile，或使新组件加载失败 | 冲突保留用户修改；观察到兼容恢复，或错误提供明确恢复路径 |
| U-06 | 升级含自定义/停用配置的旧独立更新器 | 没有重复注册；无关值和停用选择不变 |

DSH 核心和原生二进制继续通过已验证桌面安装器更新。组件回滚不等于允许降级数据库或已发布的 Session 格式。旧候选审批不授权替换后的字节或新配置修订。

<a id="data"></a>
## B：草稿、退出保护与备份

用户结果：中断的工作可恢复，且不会替换更新的文件。扩展[笔记客户端](../../../../frontends/notes/src/client.tsx)、[笔记存储](../../../../frontends/notes/src/vault.ts)、[Office 状态](../../../../frontends/office/src/services.ts)、[Office 客户端](../../../../frontends/office/src/client.tsx)、[WatchDog 受理](../../../../frontends/dsh/src/navigation.ts)和[企业备份恢复](../../../../frontends/dsh/src/enterprise-host.ts)。

### 草稿设计与顺序

1. B1 在不可变运行时/版本目录之外定义产品拥有的草稿存储。记录包含工作区/Session/文档身份、原文件修订、草稿修订、保存时间和草稿格式版本。草稿元数据不得持久保存模型凭证。
2. B1 将受理前的 WatchDog 输入和笔记编辑与已提交内容分开保存。写入合并间隔、保留策略和大小上限使用经过验证的设置。显示最近一次成功保存草稿的时间，记录实测的末尾输入丢失窗口。
3. B1 将恢复草稿作为待用户确认的内容。原件已变化、删除或移动时不能静默覆盖。保存使用现有修订检查，成功提交后仅清除对应草稿修订。
4. B2 首先检查固定 Office SDK 能否为每种支持格式导出可用恢复副本。通过同一已认证 Host 保存副本，再在真实 Tauri WebView 中验证打开和保存。不支持可靠恢复的格式保留明确导出和退出保护，不承诺恢复。
5. B1/B2 为关闭标签、退出应用和更新重启使用同一退出决定。取消时保留编辑器；草稿写入失败时，应在退出被描述为已保护之前报告错误。

### 备份范围与恢复顺序

| 数据 | 计划处理方式 | 必须保留的限制 |
| --- | --- | --- |
| 笔记、建议、批注和受管草稿 | 包含来源路径、修订与校验值 | 外部 Vault 位置保持独立于运行时存储 |
| CRM/ERP 与命令回执 | 复用企业一致性快照/恢复路径 | 保持恢复代次单调递增并拒绝过期审批 |
| Session、profile、设置及受管附件 | 清点存储所有者，协调暂停写入或使用所有者快照 | 复制活动文件不能算作一致性备份 |
| 任意外部工作区 | 明确选择，或在备份清单中明确排除 | 不暗示备份整台电脑 |
| 外部 OpenViking 服务 | 单独使用服务拥有的导出，或标为排除 | 服务健康不等于备份可恢复 |
| 凭证与操作系统绑定密钥 | 不进入日志和普通归档；要求明确的受保护机制或重新授权 | 不承诺跨机器解密 |

B3 在改动数据前验证完整备份，展示包含/排除的来源，并先恢复到隔离位置。恢复已有 profile 时必须核对当前修订，且保留可恢复的恢复前状态。不得重新激活旧单次审批、自动续跑结果未知的写入，也不得把归档可列举描述为恢复成功。

### 必须覆盖的用例

| 用例 | 准备与操作 | 必须观察到的结果 |
| --- | --- | --- |
| S-01 | 编辑 WatchDog 输入/笔记，切换 Session、关标签、退出并重开 | 草稿身份和文字在声明的保存窗口内保留 |
| S-02 | 确认草稿写入后强制停止，再重开 | 提供恢复；不替换为空文件，也不自动执行业务写入 |
| S-03 | 恢复前从外部修改原文件 | 双方内容均可取回；修订冲突阻止静默替换 |
| S-04 | 在已安装 Tauri 中编辑 DOCX/XLSX/PPTX，取消关闭、保存并重开 | 每种受支持格式保留被测内容；明确恢复限制 |
| S-05 | 将备份恢复到空的隔离数据目录 | 逐项比较声明来源、记录、附件与排除项；明确重新授权需求 |
| S-06 | 恢复后复用旧审批、修订或已提交命令 | 不重复写入；已有代次与幂等保护继续有效 |

<a id="watchdog"></a>
## C：WatchDog 工作事项与人工验收

用户结果：主页面能回答哪些事项需要处理、哪些成果可以检查。扩展[工作台](../../../../frontends/dsh/src/Workbench.tsx)、[Session 展示](../../../../frontends/dsh/src/services.ts)、[业务工具](../../../../frontends/dsh/src/enterprise-tools.ts)和前端本地化词典。保留正文空间，思考、记忆注入和命令行细节维持折叠。

### 拟议元数据与行为

| 概念 | 拟议归属与行为 |
| --- | --- |
| 工作身份 | 插件拥有的稳定引用，关联现有 DSH Session；不确定重试沿用受理请求身份 |
| 目标与范围 | 目标、选定证据/资料范围和验收条件；仅适合长期目标时使用 DSH Goal |
| 责任与时间 | 本地负责人标签及明确的到期时间/时区；均不创建账号、租户或角色权限 |
| 执行 | 从 DSH 事件/投影派生运行、待处理、失败和阻塞信息；不创建第二个执行循环 |
| 成果 | 指向文件、业务记录、已记录工具/审批结果的版本化链接；证据缺失或变化可见 |
| 人工验收 | 待复核、已接受或要求修改，包含操作者/时间及已复核成果版本引用 |

C1 仅持久保存 DSH 尚不拥有的产品元数据与验收决定。实施前定义 schema/版本、预期修订、事件重放及 fork/归档行为。新增模型可见状态必须能从 Session 日志重建。DSH Goal 完成与人工业务验收保持独立。

C2 在现有主工作区展示待审批、阻塞、逾期和待验收。AI 提交成果供复核，已认证用户在原工作事项中接受或要求修改。成果改变后，旧成果的验收不能自动适用于新版本。面向用户的操作必须由 Host 强制执行，不能仅在模型界面中隐藏。

C3 使用 Schedule 的实际回执和到期时间。固定间隔不是工作日日历计划。已关闭或冷 Session 显示等待会话恢复；界面不宣称退出的应用仍在巡检业务数据。结果未知的写入必须先核对回执再重试。

### 必须覆盖的用例

| 用例 | 准备与操作 | 必须观察到的结果 |
| --- | --- | --- |
| W-01 | 创建含负责人、期限和标准的虚构客户跟进任务，再重启 | 元数据和原 Session 保持关联；无重复任务 |
| W-02 | 读取 CSV 与 CRM/ERP，形成发现并请求经批准的改动 | 证据链接标明来源修订；拒绝/取消的写入不改记录 |
| W-03 | AI 结束执行；用户拒绝成果，再复核新修订 | 空闲/Goal 完成不等于验收；强制执行与修订绑定的验收 |
| W-04 | 丢失受理响应或双击提交 | 复用原请求确定受理结果；不再创建 Session 或命令 |
| W-05 | Session 冷置期间提醒逾期，随后恢复 | 等待/逾期状态准确；交付和工作成功分别取证 |

## D：安卓更新发现与系统确认安装

用户结果：安卓能发现下一版本，把经过验证的 APK 交给系统安装器。使用[安卓发布源码](https://github.com/NSIETeam/ClawMaster-Desktop/tree/android-v0.2.2/apps/android)，不在仅含桌面的 checkout 中开发。保留已有 Office、审批和系统任务行为。

1. D1 在设置中增加更新入口，显示当前/最新版本和发行说明。更新发现绑定独立安卓通道，不把桌面 Latest 标签作为安卓版本权威。
2. 用户确认后，下载到有容量上限且可取消的私有存储。按选定的信任设计验证清单真实性、APK 身份、versionCode、包摘要和受信发布证书；只有服务器提供的 hash 不足以建立信任。
3. 将已验证 APK 交给安卓系统确认流程。应用返回时重新检查已安装版本是否改变。缺少安装来源权限、用户取消或安装失败均不能报告成功。
4. D2 在真实设备上，将最终正式签名候选覆盖安装到公开 0.2.2 APK，不先卸载。保留 CI 模拟器检查并更新升级起始版本，不能用临时 CI 签名代替最终产物验收。

| 用例 | 准备与操作 | 必须观察到的结果 |
| --- | --- | --- |
| M-01 | 检查、下载并接受有效的更高版本 | 选择安卓通道；系统请求安装；观测到已安装版本才确认成功 |
| M-02 | 错误包名/证书、损坏 APK、降级、取消或拒绝权限 | 原应用和数据不变；没有静默安装 |
| M-03 | 用最终签名 APK 覆盖公开 0.2.2 并冷启动 | 笔记、聊天、密钥、文档、任务和待审批仍可用；不重复写入 |
| M-04 | 使用授权真实模型和虚构 Office 文件，批准/拒绝修改、导出并外部打开 | 验证真实回复与导出内容；记录设备/系统及精确 APK hash |
| M-05 | 离开界面、取消工作、断网，并让计划任务自然到期 | 观察实际续行/延迟/失败和结果保留；不承诺后台精确准点 |

已安装 0.2.2 的用户需要先手动覆盖升级一次才能取得此入口。本计划不承诺安卓兼容桌面 DSH 插件、远程桌面控制或跨设备同步。

<a id="release"></a>
## E：发布与安装验证

用户结果：每个宣传的下载都能取得对应版本且经过验证的安装包。扩展[桌面工作流](../../../../.github/workflows/desktop-release.yml)、[安卓工作流](https://github.com/NSIETeam/ClawMaster-Desktop/blob/android-v0.2.2/.github/workflows/android-validation.yml)，以及官网现有[资产校验器](https://github.com/NSIETeam/ClawMaster/blob/51c0082b7bac99d571ceccac03621c105e234804/scripts/verify-product-site.mjs)和 [Pages 工作流](https://github.com/NSIETeam/ClawMaster/blob/51c0082b7bac99d571ceccac03621c105e234804/.github/workflows/pages.yml)。

E1 定义一份发布计划产物，记录各平台版本、源码提交、CI 运行、预期文件名、摘要/签名证据以及更新或保留的决定。安卓和桌面标签保持独立。正式安卓签名/发布与模拟器验证采用不同 job，私有签名材料不进入日志或公开产物。

E2 在发布前验证最终产物。E3 仅在预期公开文件存在且可完整下载后切换服务器/官网指针。把已有在线校验器接入交付流程；临时元数据失败时保留此前已知可用的站点/指针。不得静默使用旧资产满足新平台条目。

| 平台/路径 | 下一候选必须完成的验收 |
| --- | --- |
| macOS Apple Silicon | 已安装 Tauri 启动、真实 Office 编辑/保存/重开/冲突/恢复、审批、取消、正常退出与二次启动 |
| Windows x64 | 在干净 Windows Sandbox 中执行相同用户路径；托管 runner 安装属于独立证据 |
| Linux x64 AppImage 和 DEB | 原生桌面安装/启动及产品交互；仅解包/Host 检查不足以验收 |
| Android | 最终证书设备覆盖安装、真实模型 Office 流程和 Android 8/16 模拟器回归 |
| 更新服务器 | 精确签名的版本文件先于指针切换；旧更新客户端仍受支持；候选失败保留旧通道 |
| 官网 | 计划版本已公开；名称、版本、大小、hash、链接一致；部署的 HTML/清单匹配已审查官网提交 |

在干净机器测试首次依赖准备，包括断网和恢复。固定候选后至少进行 48 小时混合使用观察，大部分负载使用录制模型，真实模型检查另行授权。记录内存峰值、子进程、任务/草稿恢复、失败和观察空缺。Host RSS 不等于总内存用量，部分观察不能写成长期测试通过。

历史 [Issue #21](https://github.com/NSIETeam/ClawMaster/issues/21) 包含迁移到 DSH 前的 Rust 执行路径和旧体积目标。PREP 将仍适用的安装、模型、数据和权限要求映射到当前发布计划。不能因架构改变就关闭尚未满足的要求，也不能把过时运行时假设套用于新的 DSH 工作。

<a id="execution"></a>
## 执行与证据

从选定的桌面、安卓和官网 ref 建立隔离分支。保留无关脏文件、现有凭证和用户正在执行的工作。集成人员负责跨仓库顺序，各工作包负责人记录依赖和审查结果。独立工作包分别提交，受影响代码同步维护完整中英文文档。

下表是候选检查入口，不代表本规划改动运行过这些命令。实施者应阅读所选 ref 的 package scripts 和[测试策略](../../../../docs/testing.zh.md)，再选择针对行为、构建产物、必要录制会话快照和原生路径的检查。不得为验证文档而对用户数据执行真实更新或备份恢复命令。

| 工作 | 需要扩展的现有检查归属 |
| --- | --- |
| A | [更新脚本/测试](../../../../frontends/updates/package.json)和[桌面脚本](../../../../apps/desktop-tauri/package.json)；新增停止 Host 后应用的验收 |
| B | [笔记测试](../../../../frontends/notes/package.json)、[Office 测试](../../../../frontends/office/package.json)、[前端测试](../../../../frontends/dsh/package.json)；新增崩溃恢复和隔离恢复 |
| C | 前端受理/业务测试及无密钥 Session 输出用例；新增验收状态持久化和陈旧成果拒绝 |
| D | 固定安卓发布源码的单元/设备测试及工作流；新增最终签名升级和安装器交接 |
| E | 桌面矩阵、安卓矩阵和官网校验器；新增计划平台完整性与公开下载检查 |

每个验收用例保存一份证据记录：工作编号、用例编号、源码提交、命令或手动步骤、实际结果、测试数据、系统/设备、产物 hash、实际运行版本、日志/截图位置和剩余限制。私密日志及凭证不进入公开证据。空白字段和未勾选用例表示待完成，不表示通过。

每个工作包按下表交接：

| 字段 | 必须填写的内容 |
| --- | --- |
| 范围 | 工作编号、入口文件、精确 ref 和明确排除项 |
| 前置条件 | 已完成依赖、测试账号/设备可用性及测试所需数据备份 |
| 结果 | 行为变化、持久数据变化、迁移和取消语义 |
| 验证 | 逐例通过/失败/阻塞、精确证据，并区分 fixture、已安装应用和真实服务 |
| 恢复 | 停用/恢复候选的步骤和数据格式兼容限制 |
| 交付 | 分别记录本地改动、提交、推送、合并、公开产物和安装验证 |

### 现有集成与产品限制

验证一个已经授权的飞书集成，从收到消息经过任务、审批直到结果送达，不承诺新的平台支持。macOS 微信读取器仅在授权选定的测试聊天中验证；扫码登录、机器人授权和个人可见消息读取是不同路径。未验证集成继续明确标为未验证或试用。

OpenViking/Graph Memory 工作限于现有检索行为、可理解的启用状态、来源标注和实测成本。不默认启用外部服务，不创建另一个记忆引擎。只读检查和隐藏工具细节不削弱服务端授权。

## 考虑过的替代方案

**广泛新增功能：**多人租户权限、同步、常驻服务器执行器和所有 IM 渠道会把新的安全/存储系统与当前恢复工作混在一起。暂缓这些能力，使本次迭代具备有限、明确的验收范围。

**重建 Agent 运行时：**第二套模型循环、任务调度器或插件管理器会重复 DSH 并增加升级工作。扩展已有公开服务和产品插件，新增持久元数据只覆盖这些服务尚不拥有的业务概念。

**把版本标记和重启当证据：**平台版本号相同或暂存后重启，不能证明组件已应用、APK 已发布或工作已验收。必须观察版本、检查最终产物并取得明确人工验收。

<a id="acceptance"></a>
## 验收标准

发布负责人针对所选候选记录以下各项。必须用例失败时，不得交付对应承诺；主动暂缓的功能必须先从发行宣传中移除，再发布。

- [ ] PREP 记录 ref、平台决定、负责人及映射后的当前发布要求。
- [ ] A1–A3 通过 U-01 至 U-06，具备真实激活与有界恢复证据。
- [ ] B1–B3 通过 S-01 至 S-06，声明恢复窗口及备份包含/排除项。
- [ ] C1–C3 通过 W-01 至 W-05；用户能查看证据，并独立于 Agent 执行状态验收成果。
- [ ] 纳入安卓更新时，D1 通过 M-01/M-02；宣称发布安卓新版时，D2 通过 M-03 至 M-05。
- [ ] E1/E2 完成最终产物矩阵及完整候选观察周期，或明确保留某平台旧版。
- [ ] E3 验证完整公开下载、更新通道、桌面 Latest 保持及产品官网部署。
- [ ] 文档、溯源及公开发行说明只描述已证明能力，并披露尚未验证的真实服务/平台路径。

<a id="risks"></a>
## 风险

Office 恢复依赖固定 SDK 和真实 WebView 行为。支持范围限定于已验证恢复路径，不能用成功提示替代恢复失败。一致性备份需要存储所有者协调和有界磁盘使用。绑定操作系统的凭证在迁移后可能需要重新授权。

更新恢复必须保留并发 profile 修改，并遵守已发布数据格式。不允许自动降级 schema 或重放结果不确定的写入。Schedule 与安卓系统任务的执行保证不同，应分别说明，不能暗示持续服务器运行。

最终设备、Windows Sandbox、Linux 桌面和真实模型验证需要相应环境及明确访问权限。前置条件不可用时记录为阻塞证据。macOS 公证与 Windows 发布者签名仍是独立的身份/证书工作，完成前继续展示实际签名状态。

多人/租户授权、远程审批、手机控制桌面、跨设备同步、无人值守服务器执行、不经安装器替换 DSH 核心、完整 Office/Obsidian 兼容、新记忆引擎和扩大个人聊天采集均不在本次迭代范围。Intel Mac 安装包继续不属于已公布的支持范围。在交付范围实施且证据审查完成之前，本文保持提案状态。
