# Agent Note: 企业责任历史在恢复后保留

Status: implemented

[English](2026-09-16-enterprise-responsibility-history.md) | 中文

## Problem

业务备份会替换记录及其按修订编号保存的前后审计。若将其作为唯一的责任日志，恢复备份时就会删除其间写入的证据。

## Decision

SQLite schema 3 在恢复载荷以外维护仅追加的责任表。成功写入与责任条目共用业务事务。恢复记录保留备份摘要和恢复前后的修订/代次；独立回执让响应丢失后的显式恢复重试具有幂等性。失败、拒绝和取消操作分别记录结果。请求 JSON 不能指定操作者或审批字段。HTTP 标识已认证的本机设备操作者；工具标识所属 Session 和调用，并附带服务端生成的审批引用。已有业务历史导入时标记操作者未知。

[业务备份决策](../feature/2026-09-14-enterprise-snapshot-backup.zh.md) 继续定义可移植业务快照和精确库存恢复。责任历史独立保存，该操作既不会替换它，也不会导出它。

## Alternatives considered

**把责任放在被恢复的业务审计中。** 替换该表必然丢失备份之后变更的证据。

**独立的仅追加文件。** 文件追加不能与 SQLite 修改原子提交。共享数据库事务可防止业务变更成功却没有成功记录。

## Consequences

哈希校验检测本地不一致，不能阻止可替换整个数据库的恶意机器管理员。企业留存仍需独立控制的归档。明确的保留策略实现前，历史会持续增长。迁移不会编造旧身份。治理测试覆盖恢复连续性、响应丢失重试、事务失败、伪造操作者字段、审计写入失败回滚、旧版本导入和哈希链损坏。真实组织身份提供者与桌面业务验收仍是独立的集成工作。
