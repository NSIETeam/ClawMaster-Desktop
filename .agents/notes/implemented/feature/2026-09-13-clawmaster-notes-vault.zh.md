# Agent Note: 持久化 ClawMaster 笔记与显式写入

Status: implemented

[English](2026-09-13-clawmaster-notes-vault.md) | 中文

## 问题

内置笔记库必须保留草稿、与外部编辑器共享可移植文件，并区分 agent 的修改建议与获批的笔记变更。

## 决策

[笔记组件](../../../../frontends/notes/README.zh.md)复用 DSH 认证、工具类型、审批与侧栏注册。Host 与 Client 一起交付八条 JSON 路由。`notes_write` 和 `notes_digest` 要求所属 agent 与单次批准。每个工具都纳入插件生命周期跟踪；卸载取消待处理审批，并等待进行中的操作和修订扫描。

协作型写者通过既有跨进程锁串行执行修订检查。每次笔记正文写入按读取预算检查最终 UTF-8 字节数，包括头部与追加结果，使成功写入的内容仍可读取。拒绝时已有字节与修订号不变。原子替换保护保存；无覆盖发布保护已占用目标。路径检查拒绝根目录下的链接。`.clawmaster/proposals` 中的建议 JSON 复用相同存储保护。新增时在写锁内检查累计 JSON 字节数与条目数；读取执行相同预算。它不进入笔记索引，但外部仍可访问。起草会持久化元数据，无需再次批准；只有应用时才改变源 Markdown。

可见面板轮询涵盖笔记与有界建议内容的版本号。文件系统扫描由修订请求负责；这条刷新路径无需原生监听，也避免 Windows 短路径根目录触发 [libuv 事件错误](https://github.com/libuv/libuv/pull/5152)。草稿保留在按 Session 隔离的插件内存中，可跨越并发刷新、导航、重命名与建议应用。笔记、标签和建议刷新分别完成；建议列举失败时保留错误与重试，不隐藏成功的笔记查询。冲突保留草稿和磁盘内容；显式重新载入与删除需要确认。嵌套文件夹和内联 SVG 图标复用宿主视觉约定。

阅读与写作使用面板的可用高度，文本编辑区字号为 15px。选中笔记时目录收起，重新打开时在宽面板中位于编辑器旁，在窄面板中覆盖编辑器。笔记信息收起时仍显示待审建议数量，让正文优先展示的同时保留审阅提示。应用建议仍需显式操作。全屏显示由宿主侧栏负责；笔记不增加全屏 API，也不引入独立的草稿所有者。

## 考虑过的替代方案

要求安装 Obsidian 会排除新用户。第二个服务器重复承担认证。盲目覆盖和自动替换草稿会丢失用户意图。持久草稿数据库会引入另一个内容所有者。固定保留纵向目录区域会在选中笔记后仍减少写作高度；可折叠目录保留导航入口，同时免去这项固定占用。

## 后果

未保存草稿无法跨进程退出保留。文件系统隔离、崩溃持久性、硬链接要求与指纹局限均作为显式[限制](../../../../frontends/notes/README.zh.md#known-limitations-and-deferred-work)保留。

## 验证

存储、生命周期与构建 Host 测试使用合成文件，覆盖卸载后的晚批准、笔记最终写入预算、累计建议预算、外部编辑和只改元数据时的版本变化。扫描屏障验证并发请求共享以及卸载等待完成；原生监听拒绝验证构建路由仍可使用。编译客户端测试覆盖草稿竞态、建议自动刷新与确认流程。类型检查和产物新鲜度检查通过。这些检查不构成最终安装界面的验收。
