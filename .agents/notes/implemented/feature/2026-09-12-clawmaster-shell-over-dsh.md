# Agent Note: ClawMaster shell over DSH

Status: implemented

English | [中文](2026-09-12-clawmaster-shell-over-dsh.zh.md)

## Problem

ClawMaster needs the mature DSH runtime, session, approval, tool, and plugin ecosystem without maintaining a second agent backend. The product still needs a Tauri desktop shell, ClawMaster visual identity, and enterprise IM onboarding through QR codes. Shipping the upstream desktop unchanged exposed the DeepSeek Harness name in the splash, window chrome, notifications, and Web UI.

## Decision

Prepared provenance includes an explicit inventory of component manifests and emitted bytes, dependency locks, and local patches with their source records. The publication workflow resolves its selected candidate to a full commit before compiling and checks it through `DSH_DESKTOP_RELEASE_COMMIT`. A component version alone cannot identify a locally patched or replaced artifact; the inventory retains both versions and byte digests.

Desktop provenance binds compiled artifacts to the source observed before compilation, then rejects source or artifact changes at preparation. A digest recorded only after copying cannot establish which source produced existing JavaScript. Release mode therefore requires a clean Git source set, matching full commit and tree identities, and build-stage records made by the complete harness build and product preparation. Development output retains its dirty paths and an explicit development build ID. Native icon outputs are regenerated from the source SVG and verified as artifacts, since platform encoding can vary independently of the artwork. The payload hashes a separate copy of its provenance and publishes one manifest per platform without carrying Git metadata. The [desktop README](../../../../apps/desktop-tauri/README.md#release) owns record fields and release operation.

The frontend's [ClawMaster SVG](../../../../frontends/dsh/src/clawmaster.svg) is the vector artwork source for client marks, splash, favicon and native icon generation. Keeping one source prevents independently resized or redrawn marks from drifting. The original PNG remains reference material, outside runtime rendering. Desktop asset verification requires SVG paths and rejects embedded or linked images, so an SVG wrapper cannot silently restore raster scaling. Packaging preserves the favicon's exact source bytes; the shipped client factory renders the same artwork.

Manual workspace selection uses DSH's in-app directory browser. The ClawMaster bundle disables the adaptive `directory-picker` row and mounts the existing browse backend and client surface together; the Web bundle supplies both dependencies. DSH owns path browsing, folder creation, cancellation and workspace adoption. This deployment choice applies only when the ClawMaster bundle is present; the official Web profile retains its adaptive picker.

ClawMaster owns the product presentation and Tauri shell. DSH owns runtime execution, Sessions, tools, approvals, and plugin loading. The `@clawmaster/dsh-frontend` package adds the ClawMaster icon, WatchDog navigation, and the slogan “开启AI时代的企业协作” through public client slots. Loading the product creates no default Workspace: explicit task creation allocates a directory under `$DSH_HOME/watchdog-workspaces/tasks`, then creates and prompts a normal DSH Session. Tool shortcuts preserve the current non-archived Session or lazily allocate the shared `desk` directory. Superseding navigation prevents late Session selection and model submission. The bundle enables official Schedule and time-context; DSH base supplies Goal and goal-round-driver. The `@xmanrui/dsh-im` plugin supplies Feishu, Weixin, WeCom, and DingTalk QR onboarding.

The default profile mounts `dsh-better-sidebar@0.19.1`, verified by its maintainers against DSH 0.1.5-rc.2. WatchDog is the product's only left navigation entry. Editor and browser shortcuts open the native right panel; the terminal opens the bottom panel. CRM and ERP register `clawmaster:crm` and `clawmaster:erp` through public `betterSidebar.registerTab`, with one tab of each type per Session. Existing sidebar settings own their enable switches and feature dialogs; the product dialog explicitly opens the native right-side tab and reports failures for retry. Registration neither opens tabs nor selects or creates a Workspace. CSV/TSV processing is an AI capability with no dedicated client page.

CRM and ERP use a local SQLite database under `$DSH_HOME/watchdog/enterprise.sqlite` through DSH's authenticated Fetch registry. Stock changes, immutable submitted orders, revision increments, command receipts, and before/after audit facts commit in one transaction. Revision conflicts preserve unsaved input; uncertain client writes retain the command identity for explicit idempotent retry. Database generations are monotonic, and unreadable or foreign databases fail without replacing data. This is a single-user CNY inventory and contact system with full-snapshot reads, not a multi-tenant ERP. Legacy browser records are neither deleted nor automatically migrated; the database makes new records independent of browser origin and desktop port.

With no history, the first client entry selects WatchDog once; existing selections take precedence. Tool shortcuts use the shared React DOM commit to mount the destination Session and bind its right-panel seat before opening a tab. Navigation cancellation still takes precedence.

Global-panel navigation retains the current Session's right Sidebar subtree, and each docked pane retains its visited tab bodies, so editors keep unsaved text and browsers keep iframe documents when switching tabs within that pane. Hidden bodies release layout space and focus; hidden panels dismiss menus and publish false tab visibility. The current service binding is released until the Conversation returns. This preserves the existing editor's save baseline without adding draft storage. A fixed Better Sidebar patch retains URL, title and navigation history through its public update API, keys native records by Session and tab identity, and releases records on the actual native lifetime abort. Body lifetime is narrower: moving a tab to another pane or floating surface, changing Sessions, closing tabs and quitting still require saving editor content.

AI uses `csv_process`, `enterprise_query`, and `enterprise_command` through the existing DSH tool pipeline. PapaParse owns CSV/TSV parsing and serialization. The CSV tool reads whole workspace files through the sandboxed filesystem, returns bounded previews, and saves complete outputs with observation guards and formula protection enabled by default. Enterprise tools and authenticated routes share one database owner and transaction implementation. Model queries paginate output; AI inventory writes, deletions, and order submission require one-shot DSH approval. Unavailable approval leaves records unchanged, and stale approvals cannot bypass revision checks. Unload withdraws both consumers and drains pending work before closing the database. DSH records tool calls and results, which are reconstructable from Session JSONL. The CRM and ERP right-side components provide review and manual takeover.

The Tauri payload includes the built frontend and exact plugin dependencies in the CLI resolver closure. A Node preload initializes the normal Web profile and appends missing product bundles before the supported `dsh web` entry; it preserves user dependency versions and patch policy. Fresh installations therefore do not depend on a developer's preconfigured profile. Copying excludes dependency and development directories even when the copy root is `node_modules`. `assertPreparedBundle` rejects excluded directories, symbolic links, and digests that differ from the prepared manifest; defaults and frontend artifacts participate in that digest. An explicit profile-installed package takes precedence over its patched installation copy. The [desktop README](../../../../apps/desktop-tauri/README.md#im-workspaces-and-bundled-packages) owns the supported removal, backup and installed-artifact verification procedure.

Runtime generations can also contain registered Workspace files, so their location under the application-data directory does not make them disposable caches. Cleanup reads the selected DSH home's current version-2 workspace unit and retains any runtime directory equal to, containing, or contained by a registered path, including resolved aliases. Missing registration permits a fresh installation; unreadable, unsupported or invalid existing registration stops deletion without logging stored values. Dependency invalidation and reseeding refuse protected or uncertain directories before changing their contents or the runtime manifest. The newest three unconditionally retained generations are a storage policy, not permission to remove Workspace data. Isolated Rust filesystem tests cover overlap, missing descendants, aliases, malformed registration, preserved manifests, and ordinary unreferenced cleanup.

The preload creates `$DSH_HOME/watchdog-workspaces/im` without creating a default Workspace. The desktop policy supplies this persistent directory separately to Weixin, Feishu, DingTalk and WeCom; a runtime installation directory is not a durable bot workspace. IM registers the Workspace only when a conversation needs it. Existing bots retain their saved path and use the upstream Workspace selector to change it; that operation clears chat bindings without deleting old Sessions. User patches apply last and shallowly replace the IM configuration, so the preload never repairs or merges over an explicit user choice.

Exact-version IM and Better Sidebar patches own their static product copy. IM includes client and Host dictionaries, connection status, approval and question messages, errors, setup display names, and the Slack application template. Sidebar includes supported locale dictionaries and Electron compatibility labels; Agent Teams, OpenViking, and Routing Suite have branded package descriptions. The IM Host artifact changes only source-matched string literals, leaving other executable tokens byte-identical. Package identities, DeepSeek model-provider names, licenses, permissions, protocol fields, and credential paths remain intact. User names, model output and other dynamic text are not subject to a page-wide replacement. Provenance and the production lock bind each patch to the installed bytes; focused tests cover rendered client copy, Host messages, metadata-only changes, and unchanged executable tokens.

Product-owned native strings and assets use ClawMaster in application metadata, the splash, tray, notifications, close dialog, Windows shortcuts, and installer icons. The [native-window decision](2026-09-13-clawmaster-native-window-titlebar.md) owns decorations, macOS overlay metrics, separate system and Web themes, and reopening a hidden window without another Host. Internal `dsh` commands, package names, profile data, and legacy application-data paths retain their compatibility obligations.

The desktop includes its release verification public key and leaves automatic-update endpoints empty. Startup and tray actions check endpoints before creating an updater or making requests; an empty endpoint list disables automatic updates even when a public key is present. Configured endpoints require a matching public key. The public ClawMaster-Desktop repository publishes versioned prereleases only after every configured platform build succeeds, with updater signatures, the public key, a manifest, and checksums. Tauri signatures authenticate update artifacts; macOS ad-hoc signing does not provide Apple notarization or a developer identity, and Windows has no publisher certificate. The [desktop README](../../../../apps/desktop-tauri/README.md#release) owns release operation and activation.

DSH exposes a mark slot but no hero-headline slot. The ClawMaster mark therefore scopes a `MutationObserver` to `[data-phase="hero"]` and replaces only the exact upstream Chinese or English headline. This keeps the customization outside DSH source, at the cost of a visible UI regression check after an upstream text or markup change.

The desktop build selects `DSH_CLIENT_TITLE=ClawMaster` and the `clawmaster` client profile for the Web shell and dynamic plugins. The framework-free boot page captures the initial document title so that product branding is available before plugins activate and in failure reports. Build-only projection gives the PWA manifest and favicon the existing ClawMaster identity, then records the client digest; upstream Web asset sources retain their defaults. Packaging checks that digest, profile, title, manifest names, and exact icon bytes. A later browser MutationObserver cannot repair an incorrectly branded first frame. Boot snapshots and hydration regressions cover initial branding; packaging tests reject upstream assets and subsequent changes. The [WatchDog tutorial decision](2026-09-13-watchdog-first-run-tutorial.md) owns the single product introduction, persistent acknowledgement, and preservation of model settings.

The [local Office decision](2026-09-13-clawmaster-local-office-editing.md) owns local conversion, protected binary saves and Office distribution obligations.

## Alternatives considered

**Keep the previous ClawMaster runtime.** This would preserve full ownership but duplicate DSH session, tool, approval, and plugin work, which conflicts with the maintenance goal.

**Ship the upstream DSH desktop without branding.** This would minimize code, but the application would identify itself as DeepSeek Harness during launch and normal use.

**Fork the DSH Web client.** This could replace every string directly, but it would create a second Web UI and turn upstream upgrades into recurring merge work.

**Restore editor drafts from a new persistence layer.** Retaining the existing component during global-panel visits and tab switches within one pane preserves its draft and save baseline together. A separate draft store would also need to detect disk changes made while the editor was absent and could otherwise silently replace the current save baseline.

## Consequences

The desktop pins Agent Teams, OpenViking Memory and Routing Suite alongside the existing IM and sidebar plugins. Deployment-owned patches adapt Routing and OpenViking history reads to public Session Projections; the original packages' `session.events` reads cannot reconstruct current Sessions. Routing includes the first claimed user message before assembly and records its guidance in the ordinary system message. OpenViking preserves the request-series marker when appending memory. Fixed patches and production dependency resolution are installation inputs; the desktop binds DSH peers to its own workspace packages rather than accepting a second prerelease core.

OpenViking remains visible but disabled through a desktop policy bundle until a separate memory service is configured. User patches apply after that policy and can enable it. Merely installing the package does not create an embedding service or make memory retrieval available. Agent Teams' disk-backed state and public tools are reused; an empty staged team's upstream deliverable flag does not constitute completed work. Routing adds task guidance in its selected preset, not multi-model dispatch. The [desktop README](../../../../apps/desktop-tauri/README.md) owns versions, activation and service requirements.

The macOS local-service helper prepares a private external OpenViking deployment with a pinned local 512-dimensional embedding model and a credential-free launchd job draft. Explicit launchd loading owns an independent loopback daemon with API-key authentication. At each start, the runner reads the existing DSH DeepSeek credential into the server environment; provisioning creates a dedicated USER client credential without giving the plugin the root key. Preparation, serving, diagnostics and provisioning leave DSH profiles unchanged. The external server is AGPL-3.0 and the integration plugin is Apache-2.0; their licenses remain distinct. Service preparation and authenticated health are separate from DSH capture, recall and packaged desktop acceptance.

DSH plugin compatibility follows the live profile because ClawMaster does not proxy the plugin protocol. Peer ranges alone do not prove compatibility or incompatibility. The audited `dsh-stall-guard@1.3.0` uses obsolete status and user-message APIs. Runtime reproductions also reject `dsh-scheduled@0.1.4` because its runner reads removed `session.events`, and `dsh-cron@0.8.0-alpha.4` because target extraction omits the current `session.header.cwd`; its automation dependency also retains removed `persistence.inspect` recovery calls. These packages are not defaults. Official Schedule supplies durable fixed-interval reminders while the app and root Session remain live; it does not provide a background daemon or outside-session notifications. The frequency selector submits a logged user request to the ordinary model/tool path and does not claim that a reminder exists before the tool succeeds.

Enterprise IM credentials remain in the plugin and DSH home. Each platform connection requires a rendered QR code and an operator-completed scan for acceptance. Focused tests cover real CSV parsing/export, SQLite contention and rollback, uncertain HTTP writes, navigation supersession, and compiled product slots. The startup smoke uses a private DSH home and real authenticated carrier; desktop acceptance additionally requires the packaged Tauri app, its first frame, and interactive editor/browser/business workflows.
